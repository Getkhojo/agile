# agiletechexpert.com — Team Guide

How to change, build, deploy and fix the website. Read this before your first change.

Last updated: 2026-10-25

---

## 1. What this is

A static website (plain HTML, CSS, JavaScript) generated by one Python script.
There is no framework and no Node build. nginx serves the generated files.

| Part | Technology | Version |
|------|------------|---------|
| Site generator | Python | 3.12 or newer (built with 3.13) |
| Image processing | Pillow | 12.x (`pip install pillow`) |
| Web server | nginx | Ubuntu package version |
| SSL | certbot (Let's Encrypt) | Ubuntu package version |
| Fonts | Google Fonts: Michroma, Outfit, Plus Jakarta Sans | loaded from fonts.googleapis.com |
| Browser JS | Vanilla JavaScript, no libraries | — |

Repository: `github.com/Getkhojo/agile` (branch `main`)
Server path: `/var/www/agiletechexpert`
nginx serves: `/var/www/agiletechexpert/public`

## 2. File map

```
content/site.json          Company name, phones, email, address, WhatsApp, social links, GA4 ID, Search Console code
content/services.json      All 12 services: titles, text, features, use cases, FAQs, SEO description
content/team.json          Team members
content/gallery.json       Gallery photos and captions
src/assets/css/site.css    All styles
src/assets/js/site.js      Page behaviour: menu, background motion, forms, logins
src/assets/js/chat.js      Chat + voice assistant widget
src/assets/img/            Background images (bg.webp desktop, bg-mobile.webp phone)
src/assets/team/           Team photos (create the folder when adding the first photo)
src/assets/gallery/        Gallery photos
tools/build.py             Builds the site into public/ (HTML layout of every page lives here)
public/                    GENERATED. Never edit by hand. Committed to git so the server only pulls.
deploy/nginx-agiletechexpert.conf   nginx site config
deploy/deploy.sh           Server update script
docs/BACKEND.md            API the frontend calls (/api/leads, logins, assistant)
```

Rule: **edit `content/` or `src/`, run the build, commit both the source change and `public/`.**

## 3. Making a change

```bash
pip install pillow                        # first time only
python3 tools/build.py                    # rebuild public/
python3 -m http.server 8080 -d public     # preview at http://localhost:8080
git add -A
git commit -m "Short description of the change"
git push
```

Then on the server:

```bash
sudo bash /var/www/agiletechexpert/deploy/deploy.sh
```

### Common edits

| Task | Where |
|------|-------|
| Change phone, email, address | `content/site.json` |
| Add a social link | `content/site.json` → `social` (empty = hidden) |
| Edit a service's text or FAQ | `content/services.json` |
| Add a new service | Add an object to `services` in `content/services.json`; `slug` becomes the URL `/services/<slug>/`; `icon` must be a key in `ICONS` in `tools/build.py` |
| Add a team member | `content/team.json`; photo → `src/assets/team/name.webp` (square, ~400px), set `"photo": "name.webp"` |
| Add gallery photos | Put `.webp` (~1600px wide) in `src/assets/gallery/`, set `src` in `content/gallery.json` |
| Change colours or spacing | `src/assets/css/site.css` (colour variables at the top in `:root`) |
| Change page layout or add a page | `tools/build.py` (each page is a `page_*` function; add new public pages to the sitemap list in `main()`) |
| Google Analytics | `ga4_id` in `content/site.json` |
| Search Console verification | `google_site_verification` in `content/site.json` |

## 4. How the forms and logins work

- **Inquiry form and chat** send a JSON `POST` to `/api/leads`. If the API is down or returns an error, the visitor is offered a WhatsApp link with the same details, so no inquiry is lost.
- **Employee login** posts to `/api/auth/employee/login`; **client login** to `/api/auth/client/login`. They are separate on purpose; never merge them.
- **Chat assistant** answers from the site content inside the browser. To route it to the AI backend, set `assistantEndpoint` in `config_js()` in `tools/build.py` and rebuild.
- **Voice button** uses the browser's speech recognition (works in Chrome and Edge). Safari/Firefox users are asked to type.

Full API details: `docs/BACKEND.md`.

## 5. Troubleshooting

| Problem | Check | Fix |
|---------|-------|-----|
| Change not showing on the site | Did you run the build and push `public/`? Did `deploy.sh` run? | Rebuild, commit, push, run `deploy.sh`; hard-refresh the browser (Ctrl+Shift+R) |
| `python3 tools/build.py` fails with `No module named PIL` | Pillow missing | `pip install pillow` |
| Build fails with JSON error | A comma or quote is wrong in `content/*.json` | `python3 -m json.tool content/services.json` shows the line |
| Build fails with a syntax error in `build.py` | Python older than 3.12 | Use Python 3.12+ |
| Background or icons missing | Browser console (F12) shows 404 on `/assets/...` | Confirm the file exists in `src/assets/`, rebuild |
| Site shows "502" or "404" for every page | nginx root path wrong | `sudo nginx -t`; root must be `/var/www/agiletechexpert/public` |
| HTTPS certificate expired | `sudo certbot certificates` | `sudo certbot renew` (auto-renew runs via systemd timer) |
| `deploy.sh` says "Permission denied" on git | Server's GitHub access expired | Update the token or deploy key on the server |
| Form says "couldn't reach our server" | Backend API not running | Check backend service status; WhatsApp fallback keeps working meanwhile |
| Voice button says "not supported" | Visitor's browser | Expected on Firefox/Safari; they can type |
| Microphone "blocked" message | Browser permission | Visitor allows the mic for the site in browser settings |

### Useful server commands

```bash
sudo nginx -t                                  # test nginx config
sudo systemctl reload nginx                    # apply config
sudo tail -n 50 /var/log/nginx/error.log       # recent nginx errors
sudo tail -n 50 /var/log/nginx/access.log      # recent requests
cd /var/www/agiletechexpert && git log -1      # which version is live
```

## 6. Rules

- Never edit files in `public/` by hand; they are overwritten by the build.
- Keep code, comments and commit messages in English.
- Do not commit passwords, API keys or `.env` files.
- Login pages and `/portal/` must stay out of Google (`noindex` + `robots.txt`). Don't remove that.
- Test on a phone-width window before pushing.

## Staff portal (quick guide)

- Sign in at `/portal/employee/`. You land on the staff portal.
- **Leads**: change the status as you follow up and add a short note. Use the search box to find a lead.
- **AI conversations**: open any chat or voice call to read it. Mark the AI's answer 👍 or 👎 and write what it should have said; this is how we improve the assistant. "Off-topic?" means the visitor may have asked something unrelated; check and rate it.
- Admins also have **AI usage & cost**, **Users & accounts** (create logins, reset passwords, disable accounts), **Billing** (client invoices with GST) and **Activity log**.
- Forgot password: ask an admin to set a new one in Users & accounts.
